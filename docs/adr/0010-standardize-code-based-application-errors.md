# Standardize public application failures by error code

Own one public failure contract in `lumina-app`, with required stable `errorCode` values, human-readable `message` text, and code-specific typed `data` where needed; generate its TypeScript representation instead of maintaining parallel code catalogs. Domain, persistence, and native implementations retain appropriate internal typed errors and causes, translating them deliberately into the public application contract; the desktop and frontend bridge adapters handle serialization and unexpected invocation failures centrally. This keeps UI decisions independent of message wording while preserving useful diagnostics, accepting an explicit mapping at integration seams instead of one catch-all error type or message parsing throughout the UI.
