# Lumina specification v2: independent audience workspaces

Status: ready-for-agent

This is the cumulative behavior contract for iteration 2, combining the first-session MVP and all accepted second-session decisions Q63-Q83 through October 15, 2026. It can be read on its own. The original spec is historical; where earlier documents describe a single audience or application-global appearance, this version governs.

This document specifies the next iteration; publishing it does not itself start implementation or claim native verification. Final UI review and native qualification remain implementation/review work.

## Problem Statement

An operator needs to find and project Bible verses during a gathering without exposing preparation to the audience. The workflow must remain usable without an account or network connection, support English and Tagalog translations, and preserve the useful capabilities of the existing digital Bible application.

The reference application's search surfaces provide a functional baseline, but its documentation does not establish its internal search algorithms. A separate first-iteration Lumina prototype now demonstrates a single-audience workflow. The second iteration needs several independently controlled audiences: changing one room's passage, translation, queue, or appearance must not change another room's presentation. Operators also need reusable preparation and predictable shared Bible maintenance.

## Solution

Build an open-source desktop application with one tabbed operator window. Each operator tab represents an independent operator workspace associated with at most one local audience window. There is no application-imposed count cap; usable simultaneous outputs depend on hardware/OS resources. Start with one workspace, and create more explicitly. Bundle a usable Bible, share one installed Bible library across workspaces, and keep the core workflow local.

Within each workspace, keep private preview independent of live content, with separate navigation controls. Search, queue, and history selection prepare privately; Send Live projects explicitly. Quick reference still projects directly on Enter. Switching tabs changes only which workspace is controlled; other audiences retain their output. Persist each workspace's agreed saved state by stable identity, restore tabs after restart with every audience closed, and preserve original captured wording across shared Bible changes.

## Implementation Decisions

- Keep the existing Tauri desktop and React interface foundation. Inspect the implementation checkout before changing it: the documentation checkout is not the separate first-iteration prototype. Reuse working baseline features and address gaps against this cumulative contract rather than assuming all of iteration 1 is absent or fully verified. The reference digital Bible application and Lumina's prototype are separate evidence sources.
- Group implementation around local Bible storage/reference/search, the operator workspace, audience output/native display controls, and persisted workspace/appearance. Use the existing native-command bridge where native storage or window operations are needed. Detailed command contracts and module boundaries remain engineering design work; no new dependency is selected merely by this spec.
- Respect the decisions to keep the core workflow local and account-free and to preserve original history text. Reference resolution and search retrieval must remain separate from audience projection.
- Use an app-managed SQLite import/storage workflow based on the supplied translation, book, and verse schema. Translations have titles and optional descriptions; books belong to translations and carry book numbers/names; verses carry book/translation identity, chapter, verse, original text, and sort order. Define the precise import contract and validation rules before implementation.
- Declare one supported book-number convention for the standard 66-book set. Local database row IDs are not cross-translation identities. Conforming imports require no manual mapping. Partial imports retain canonical coordinates; navigation follows available verses in Bible order and skips absent coordinates.
- Validate and review imports before accepting managed copies; leave supplied files unchanged. Reference and search indexes are derived app-owned data that can be regenerated. Reject unsupported book identities or inconsistent records; valid partial coverage remains acceptable.
- Give installed translations stable identity independent of title and changing text. Share one installed Bible library across workspaces. Skip exact duplicates. Distinct data with a matching title requires an explicit Add or Replace decision. Replace/Remove require confirmation and every audience window closed; Add is allowed during presentation. The bundled WEB entry remains protected and available.
- Preserve queued translation/reference identities across replacement/removal. Updated imports supply current queue text; missing data becomes Unavailable and cannot be sent live. Restoration explicitly targets the original installed entry; a separate import never silently replaces its identity. Specify duplicate comparison, replacement failure handling, and restoration mechanics as implementation details.
- Preserve original verse text, translation label, edition identity, timestamp, and preview/projection action in verse history. Repeated actions create repeated entries; typing and scrolling do not. Saved copies remain usable after removal or replacement, with an operator-only Saved copy indication when appropriate. Adjacent navigation requires that original edition still be installed.
- Keep startup/restart limited to one operator window. Restore saved workspaces and their last active selection, with all audiences closed and cursor restrictions off. Open Audience explicitly opens blank output for its workspace; projection requires that output open. Closing the operator saves the agreed persistent state for every workspace and closes all audience windows. Closing an audience preserves its preparation; recovered or reopened output starts blank until explicit projection.
- Keep quick reference in the active workspace's bottom bar reference-only. Support documented English/Tagalog names and aliases, show resolved identity, project valid unambiguous input on Enter to that workspace's audience, and require explicit candidate selection for ambiguity. Invalid, unknown, or unloaded references receive inline feedback without changing any audience content. No separate missing-reference report is required; the word-search scope does not constrain quick reference.
- Search one selected installed translation and one Search at scope, using All words by default. All words requires each complete word in one verse in any order; Phrase requires consecutive complete words in entered order; Word starts requires every prefix in one verse in any order; Contains text requires the entire normalized input as a literal contiguous substring. User text never activates raw FTS operators, SQL wildcards, or regex behavior.
- Normalize case, accents, and straight/curly apostrophes consistently across all four modes while preserving original Scripture text. Phrase matching uses normalized word boundaries rather than identical punctuation. Build engine queries internally and map highlight positions back to original text.
- Use app-owned lexical indexes; SQLite FTS5 is the recommended word/phrase/prefix foundation, subject to verifying support in shipped builds. Evaluate literal normalized lookup and a trigram index for Contains text, retaining short-query handling. Unstemmed Unicode matching is the recommended shared English/Tagalog basis. These engine recommendations do not change the accepted matching semantics or establish Android result parity.
- Define OT as Genesis-Malachi, NT as Matthew-Revelation, Books of Moses as Genesis-Deuteronomy, Gospels as Matthew-John, and Epistles of Paul as Romans-Philemon. Hebrews remains available in NT and specific-book scopes. Filters apply to available imported verses.
- Submit word searches only on Enter or Search. Query editing preserves submitted results. Translation changes clear obsolete results, retain typed text, and require another search; outdated asynchronous responses cannot refill the new translation's result view. Search, filter changes, result paging, and result selection do not project automatically.
- Show original text with highlighting, reference/translation, count, and inline query/translation/scope summary. Preserve numbered pagination and all qualifying results. Best match is the default; Bible order and an NT jump in that order are available. Phrase occurrence, proximity, lexical relevance, and Bible-order ties are ranking recommendations; weights, page size, and Contains text ranking require evaluation rather than invented quality guarantees.
- Keep live content and private preview independent within each workspace. Search, queue, and history selection update its private preview; Send Live or Ctrl/Cmd+Enter projects that captured text to its audience. Each Previous/Next pair uses its own translation/edition and preserves the other target. Ordinary translation selection is preparatory; Change translation beside the live reference stages the same reference privately, then requires Send Live. Missing content leaves audience output unchanged; other workspaces remain untouched.
- Provide verse-text family, size, bold/italic, color, underline, and strikeout independently per workspace. Reference and translation labels retain fixed application styles/sizes. Editable character-count size bands show current length and active band; manual adjustment changes the shared band for verses within that workspace and persists, without changing another workspace. Evaluate initial ranges, values, and rendering units visually; do not treat legacy screenshots or demo values as shipped defaults.
- Keep one complete verse on one slide, using sensible defaults and manual size reduction. Font defaults are shared within a workspace; backgrounds are per translation within that workspace, with a readable fallback. Accept managed copies of JPEG, PNG, and BMP, with Fill/crop default and Fit available. Appearance changes preview privately until Apply changes that workspace's audience; Cancel discards them. Image decoding and limits require implementation design.
- Use local native audience windows on the operator computer's OS extended desktop, with manual placement followed by fullscreen. Each workspace controls its associated audience's Blank/Resume, fullscreen, and hidden cursor. Operator always-on-top retains its baseline meaning for the single operator window where supported.
- Give every workspace an independent manual cursor-restriction toggle, initially off and enabled only while its audience is open. Each enabled choice prevents hover over its own audience while allowing normal use of other applications. Enabled restrictions compose: toggling or closing one must not release another. Tab switches, fullscreen, and application switches preserve choices; closing/disconnecting an audience or removing its workspace resets only its own restriction off. Reopening starts off; app restart starts all restrictions off. A global-toggle recommendation was explicitly rejected.
- Native cursor feasibility must satisfy the accepted behavior on every configuration claimed as supported. A browser demonstration or successful cursor-grab API return is insufficient. The inspected Tauri cursor-grab behavior does not establish the required cross-application audience exclusion; investigate platform integration without silently dropping the feature or claiming unsupported configurations.
- Retain F1, F3, F7, and operator-focused Ctrl/Cmd+Enter. F7 uses optional import-supplied book name, author, writing date, and location with source attribution; absent fields show Information unavailable and never block Bible use. Define the optional metadata/provenance contract before implementation.
- Use one physical operator window with Chrome-like operator tabs, each representing one independent operator workspace and at most one associated audience window. Audiences may show unrelated references/translations; no synchronization is implied. Start with one workspace; additional workspaces and audience windows are explicit. Keep at least one workspace.
- Do not impose a numeric count cap on workspaces or audiences. Practical capacity depends on hardware/OS resources, retained state, and simultaneous native rendering. Handle reported additional-window creation failures visibly for that workspace and avoid deliberately disrupting existing outputs. No promise is made that arbitrary resource exhaustion is recoverable. Publish actual tested counts separately from the absence of a product cap.
- Own selected translation, search query/mode/scope/results/page, private preview, live content/navigation, queue, history, and appearance within each workspace. Switching the active tab changes only the controls being operated; inactive audiences continue unchanged. Quick reference, Send Live, shortcuts, and navigation target the active workspace. Late search or native responses must remain bound to the initiating workspace even after a tab switch.
- New workspaces have empty search/previews/live content, queue, and history; bundled WEB and application-default appearance; and a closed audience. Give default Audience N names that operators can rename. Workspace names are operator identification, not extra labels on projected Scripture. Dedicated workspace cloning is not included.
- Close Audience closes only that output and preserves the workspace. Closing/removing an operator tab requires confirmation, closes its audience, and deletes only its saved preparation/history. Other workspaces and the shared Bible library remain unchanged. Do not allow removal of the final workspace.
- Persist workspace identities, names/order, queue, history, selected translation, confirmed appearance, and last active workspace selection. Associate state with stable identity rather than tab number or name; a workspace moved from position 20 to position 3 retains its own state. Search results, live output, and private preview are runtime state and are not added to the cross-restart persistence promise. Retain the imported Bible library. Fresh-session startup discarding saved workspaces was considered and rejected.
- On detected audience-display loss, close only affected outputs and preserve their workspaces; unaffected audiences continue unchanged. Reopening/recovering affected output starts blank and with restriction off until explicit operator actions. Verify window-to-display mapping and detection natively; the single-audience prototype's global monitor-change handler does not establish isolation.
- In Manage Bibles, Replace means selecting an installed imported Bible, choosing Replace and an updated SQLite file, reviewing the proposed replacement, and confirming while all audiences are closed. Update the same installed entry rather than inferring replacement from a matching title. Preserve source files and the shared Bible's installed identity.
- After removal, change affected workspace translation selections to WEB for future search/reference lookup. After replacement, retain the selected installed entry with updated data. Clear obsolete results while preserving typed query/mode/scope; require deliberate search again. Never convert queued translation identities or captured text into WEB automatically.
- Already-loaded private preview and history retain captured wording and translation labels after maintenance. Show Saved copy when the source edition is unavailable; permit explicit projection/copy/export of captured text, but adjacent navigation requires the original edition. Queue entries instead resolve current installed text when available, or remain Unavailable until explicit restoration into their original installed entry. A newly selected queue/search result prepares installed wording rather than silently rewriting an existing preview.
- Keep queue editing and history filtering, clearing, copying, and CSV export workspace-specific. Repeats, timestamps, Sent Live filtering, clear confirmation, and original-wording retention follow the baseline contract independently in each workspace.
- Keep Blank/Resume individual to the active workspace. Blank All, Resume All, Send All, linked navigation, and dedicated cross-workspace copy/clone controls are deferred. Baseline clipboard Copy remains available.
- Preserve the supplied inspiration inside each active workspace: dominant live preview, right-side search/history, adjacent verses, bottom queue, and reference-only quick input. Show each tab's name and Live/Blank/Closed status, and repeat the active workspace identity beside projection controls. Keep live/private navigation targets clear and provide usable overflow for variable tab counts. Exact layout/control placement requires UI review; unreviewed demo layouts are not accepted production designs.
- Target Windows, macOS, and Linux. Qualification starts with Windows 10 22H2/11, macOS 13.3+, and updated Ubuntu 22.04/Debian 12, evaluating Linux display sessions separately. These are candidates, not verified compatibility. Offline release packages plus any supplied dependency bundle must install and launch without fetching required runtime or Bible assets on the documented baseline.
- Bundle the publisher's WEB Protestant edition for the 66-book starter, preserving Scripture text and recording exact edition, source, acquisition date, and artifact identity before release. MIT remains the selected code license; adding its license file is separate release work. Keep application, Bible, metadata, and dependency terms distinguishable. Do not add application-level Bible encryption.

## Testing Decisions

- Follow the repository's manual-verification policy. This spec does not authorize new or modified automated test files. Existing non-test build, lint, formatting, and type checks may support implementation, but cannot prove runtime behavior.
- Use the packaged operator/audience workflow as the highest verification seam: perform operator actions and observe private preview, live preview, audience output, saved workspace, and actual pointer movement. This follows the already-agreed manual checks and release rehearsal. Prefer this seam over testing internal UI state, query strings, or particular module arrangements.
- Verify local Bible storage/reference/search, operator workspace/queue/history/appearance, native audience/display controls, and packaged offline installation through their public behavior. Where failures cannot be triggered reliably from the UI, use fixture import files or an observable native-command boundary rather than adding unnecessary production seams.
- Prior art includes the session's local MVP-scope/search manual guides and the first-iteration prototype's native observation notes. Those notes are existing evidence for its single-audience checks, not new runs or proof of iteration-2 behavior. Inspect the implementation checkout's existing seams before adding new ones.
- Exercise successful, invalid, ambiguous, and unloaded references; confirm only explicit valid projection changes audience content. Test preparation with the audience closed, independent live/private navigation, translation staging, and quick reference outside the selected word-search scope.
- Use English/Tagalog fixtures for complete words, reordered words, phrases, prefixes, literal substrings, accents, Unicode composition, apostrophes, and punctuation/wildcards. Include misspellings and paraphrases as negative cases for deferred assistance. Check result membership, completeness, ordering, pages, NT jump, and highlighting against original text; confirm no silent query relaxation or stale response after translation changes.
- Verify one/many-translation imports, differing local row IDs, unsupported book numbers, partial coverage, exact duplicates, same-title alternatives, protected WEB, and Add during presentation. Check Replace/Remove confirmation and the all-audiences-closed requirement, including an audience in an inactive tab; failures must preserve valid installed data and supplied files.
- Verify updated and missing queue references, removed translations, explicit same-entry restoration, and retained history wording/labels. Saved copies must still preview/copy/export/re-project, while adjacent navigation is unavailable without the original edition. Confirm repeats, Sent Live filtering, visible-history CSV export, and clear confirmation.
- Check Apply/Cancel and shared band effects across several verses within a workspace, while confirming other workspaces remain unchanged. ## Out of Scope

- Dedicated personal reading mode, simultaneous multi-slot content within one audience window, and reference ranges. Multiple independently controlled audience windows are included in v2.
- Separate/detachable native operator windows, network/browser/mobile audience receivers, bulk presentation actions, linked navigation, and dedicated cross-workspace copy/clone controls. Existing clipboard Copy remains included.
- Spelling assistance, fuzzy spelling correction, meaning-based semantic search, and book-name typo suggestions; known reference aliases remain included.
- Any word mode, mixed query/operator expressions, cross-translation search, cross-verse phrase matching, and language-specific stemming remain outside this iteration.
- Automatic font fitting, projection pagination, per-verse size overrides, independent reference/translation-label formatting, and the legacy Script selector.
- In-app monitor selection; MVP uses OS Extend, manual placement, and fullscreen.
- Bible book sets outside the standard 66 books and manual mapping of alternative numbering conventions.
- A curated bundled book-information dataset until a suitable redistributable source is established; optional attributed import metadata remains included.
- Account/cloud dependencies for the core workflow and application-level Bible encryption. Encryption was explicitly removed, not merely deferred.
- Automatic cursor-restriction activation or deactivation on application switching; the accepted manual toggle and closure/disconnection release behavior remain included.
- A standalone missing-reference report; missing verses receive inline feedback at attempted use.
- License-file changes in this documentation/spec work. The MIT choice remains recorded for later release work.
- Production implementation or promotion of an unreviewed demo as part of publishing this spec.

### Shared Bible maintenance example

Suppose workspace A selects an imported Tagalog Bible, already previews John 3:16, and has that reference queued and recorded in history. Workspace B uses WEB. Every audience is closed before Remove or Replace, as accepted in Q76.

| Item | Remove the imported Bible | Replace it with an updated edition |
| --- | --- | --- |
| Workspace A's translation selector | Select WEB for future search/reference lookup | Keep the same installed Bible entry selected, now using updated data |
| Search results for that Bible | Clear obsolete results; retain typed query/mode/scope | Clear obsolete results; retain typed query/mode/scope |
| Already-loaded private preview | Retain original Tagalog wording/label as Saved copy | Retain the captured old wording/label; indicate Saved copy if its original edition is unavailable |
| Queued John 3:16 | Unavailable until data is explicitly restored into that Bible entry | Resolve updated text if that reference exists; otherwise Unavailable |
| History entry | Retain original wording/label | Retain original wording/label |

The selector fallback does not convert the prepared verse or queue into WEB. A captured Saved copy can be explicitly sent live with its original translation label, while adjacent navigation requires the original edition. An unavailable queue entry cannot fetch/project missing data. Selecting a newly resolved queue/search result prepares the installed text. Workspace B is unaffected unless it also references the changed Bible.
